## 目录结构

```
docs/
├── guides/          # 操作指南、使用手册
├── specs/           # 技术规格、架构文档、设计方案
├── plans/           # 实施计划、迁移计划
├── decisions/       # 决策记录（ADR）
├── prototypes/      # 原型设计文件
├── reports/         # 验收报告、测试报告、可研报告
│   └── incidents/   # 事件复盘报告
└── notes/           # 笔记、备忘
    └── issues/      # 活跃问题追踪（解决后归档至 reports/incidents/）
```

| 目录 | 用途 | 生命周期 |
|------|------|----------|
| `guides/` | 用户手册、操作指南、快速上手 | 长期 |
| `specs/` | 设计规格、技术方案、架构文档 | 长期 |
| `plans/` | 实施计划、迁移计划、执行清单 | 中期 |
| `decisions/` | ADR 关键决策记录（为什么选这条路） | 长期 |
| `prototypes/` | 前端原型（HTML） | 按版本归档 |
| `reports/` | 验收报告、测试报告、可研报告 | 长期 |
| `notes/` | 临时笔记、背景记录、活跃问题 | 短期 |

## 命名规范

- 中文撰写、中文语义命名
- 日期前缀：`YYYY-MM-DD-文档标题.md`
- 决策记录：`ADR-NNNN-简短中文标题.md`
- 原型文件需版本化，不覆盖历史版本

## 维护约定

1. 新增文档必须归类到以上类型目录。
2. 目录结构或文档变更时，必须同步更新本文件（类别清单 + 阶段总览）。
3. 阶段状态发生变化时（如从"待启动"变为"进行中"），及时更新阶段总览表格。
4. 若文档被迁移，建议在提交信息中标注 `docs-reorg`。
5. 活跃问题解决后，应从 `notes/issues/` 移至 `reports/incidents/` 并补充复盘内容。
